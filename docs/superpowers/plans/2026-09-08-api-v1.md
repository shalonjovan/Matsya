# Public API v1 + Safe Routing + Computed Risk Zones Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose MATSYA data through a versioned open API (`/api/v1`, no keys), compute sidebar risk zones from simulation data instead of hardcoded mocks, and deliver the PS-mandated flood-safe routing endpoint.

**Architecture:** New `api_v1.py` router and `road_segments.py` / `safe_routes.py` services sit beside (never inside) the legacy `/api` paths; per-segment flood series are sampled from the stored snapshot stack; routing is time-dependent Dijkstra over segments split from `roads.geojson`; risk-zone mocks in `analysis.py` + frontend fallbacks are replaced with computed values.

**Tech Stack:** FastAPI + pytest, shapely/rasterio/numpy (already deps), heapq stdlib routing, vitest/tsc frontend.

**Spec:** PS navigation-API paragraph (chat 2026-09-07); user answers: build `routes/safe`, open reads no keys. Endpoints frozen under `/api/v1` with `{v, generatedAt, disclaimer, data}` envelope.

### Phase C: `POST /api/v1/routes/safe` (the PS deliverable)

**Files:**
- Create: `matsya/matsya/backend/app/services/safe_routes.py`, `matsya/matsya/backend/app/tests/test_api_v1_routes.py`
- Modify: `matsya/matsya/backend/app/routers/api_v1.py` (add route only)
- Test: `test_api_v1_routes.py`

**Interfaces:**
- Consumes: `build_segments(bbox)` + snapshot stack + mpf (Phase A services); request `{origin: {lat, lon}, destination: {lat, lon}, departAtMin: float = 0, simId: str, thresholdCm: float = 15.0}`.
- Produces: `find_routes(...) -> {"fastest": route|None, "safest": route|None, "reason": str|None}` where `route = {"path": [[lon, lat]...], "segmentIds": [...], "etaMin": float, "floodDelayMin": float, "maxDepthCm": float, "avoidedSegments": [...]}`; HTTP 200 always on valid input (empty routes + reason when cut off); 404 unknown sim; 422 snap beyond tolerance or missing fields.

**Graph + algorithm (exact):** nodes = segment endpoints + pairwise segment crossings via shapely, built once per sim and cached in a module dict keyed `(simId, updated)`; edge = segment slice between adjacent nodes with `lengthM` (haversine) and the parent segment depth series. Travel speed constant `SPEED_M_PER_MIN = 500.0` (30 km/h urban default, documented assumption). Earliest-arrival Dijkstra with stdlib `heapq`: state `(arrivalMin, node)`; entry step `k = floor(arrivalMin / mpf)` clamped to last step; edge blocked if `depthCm[k] >= thresholdCm`; traversal adds `lengthM / 500.0`; arrivals past the last step reuse last-step depths (documented). `fastest` = min arrival ignoring flood (`floodDelayMin = 0`); `safest` = min arrival over unblocked edges, `floodDelayMin = safest.eta - fastest.eta`, `maxDepthCm` over traversed edges at entry steps, `avoidedSegments` = fastest-route segments absent from safest route. Snap tolerance `SNAP_TOL_M = 200.0` haversine to nearest node, else 422 `{"detail": "origin outside routable network (200m)"}` (same for destination).
