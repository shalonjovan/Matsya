# Real-Time Sim + Crowdsourcing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One continuously-updating real-time flood sim (12h back/forward window, dummy weather feed swappable for API calls, live lake levels) plus click-to-report crowdsourced water updates assimilated into it.

**Architecture:** `weather.py` adapter interface (`fetch()` returns rain cells + lake states; dummy now, documented swap); `realtime.py` manager owns the singleton sim id, rebuilds its 24h rainfall from the sliding window and reruns the real flood pipeline per tick; asyncio tick loop gated behind `REALTIME_LOOP=1` (off in tests); crowd reports persist on the sim and apply as a decaying overlay after each recompute; UI gets a live panel + report form reusing `selectedPoint`.

**Tech Stack:** FastAPI + asyncio (no new deps) + pytest; React + vitest.

**Spec:** Chat 2026-09-08/09 (single realtime sim, ±12h window, dummy ≤1mm/hr mostly-dry feed, live waterbody capacity, click-point crowd reports with water amount). No merge to main.

## Global Constraints

- Branch: `real-time`. Do NOT merge to main until the user says so.
- One commit per phase; exact messages below.
- Backend uvicorn runs WITHOUT `--reload` — restart after backend edits.
- TDD: RED test first, verify fails correctly, then GREEN.
- Exactly ONE realtime sim: fixed id `realtime-chennai-01`, flagged `live: true`; normal sim flows untouched (replay/duplicate/edit never target it — guard in duplicate/delete: refuse with 400).
- Dummy data bounds: rain 0–1mm/hr, blips cover ≤10% of domain; lake fill 40–80%.
- Crowd assimilation is a documented overlay (reported depth held with 6h half-life decay onto recomputed snapshots), not fake physics.
- No new dependencies.
