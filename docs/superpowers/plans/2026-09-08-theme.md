# UI Theme + Flood Depth Palettes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Light/dark UI switch plus switchable flood-depth color themes (blue scale, green-to-red) with transparent near-zero depths.

**Architecture:** UI theme via `ThemeContext` (persisted, `data-theme` on root) + a scoped `[data-theme="light"]` override block in `index.css` (components hardcode dark utilities, so variant rewrite is out of scope); depth palettes rendered server-side to RGBA PNGs on request from stored snapshots (`?palette=blue|greenred`, blue default = legacy bytes), selected in the LayerPanel depth group and threaded through MapView flood URLs.

**Tech Stack:** React 18 + Tailwind (darkMode class present) + vitest, FastAPI + PIL/numpy + pytest.

**Spec:** Chat 2026-09-08 (light version + switch; green→red depth theme; transparent ≈0.00m). Defaults preserve current look exactly (dark UI, blue depths).

## Global Constraints

- Branch: `theme`. Do NOT merge to main until the user says so.
- One commit per phase; exact messages below.
- Backend uvicorn runs WITHOUT `--reload` — restart after backend edits.
- TDD: RED test first, verify fails correctly, then GREEN.
- Default palette `blue` serves the stored PNG bytes unchanged (zero regression risk on default path).
- Transparency threshold: alpha 0 below 0.02m depth; everything else fully opaque per palette color.
- No new runtime dependencies (PIL/numpy already used).
